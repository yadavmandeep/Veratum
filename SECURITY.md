# Security Policy

The Veratum team takes security and trust seriously. As an AI harness that monitors file access, executes commands, and enforces cryptographic tree verification, security of our runtime and hooks is paramount.

---

## Supported Versions

We provide security updates and patches for the following versions:

| Version | Supported          |
| ------- | ------------------ |
| 1.1.x   | :white_check_mark: |
| 1.0.x   | :white_check_mark: |
| < 1.0   | :x:                |

---

## Reporting a Vulnerability

**Please do not report security vulnerabilities through public GitHub issues.**

If you discover a potential vulnerability in Veratum, please disclose it responsibly through **GitHub Security Advisories**:

1. Navigate to the **Security** tab of the [repository](https://github.com/yadavmandeep/Veratum/security).
2. Click on **Advisories** and select **"Report a vulnerability"** (or click [here](https://github.com/yadavmandeep/Veratum/security/advisories/new)).
3. Provide details in the confidential draft advisory form. This allows maintainers to collaborate with you privately to verify and fix the vulnerability before public disclosure.

### What to Include in Your Report
To help us triage and resolve the issue quickly, please provide:
- A description of the vulnerability and its potential impact.
- Clear reproduction steps or a minimal proof of concept (PoC).
- The operating system, Python version, Node version, and IDE adapter used.
- Any suggested fix or remediation steps (if known).

---

## Response Timeline & Process

- **Acknowledgment**: We will acknowledge receipt of your report within **48 hours**.
- **Assessment**: We will investigate and confirm whether the reported behavior constitutes a vulnerability within **5 business days**.
- **Fix & Disclosure**: Once resolved, we will publish a security patch release and coordinate public disclosure with appropriate attribution to the reporter.

Thank you for helping keep Veratum and its community secure!
